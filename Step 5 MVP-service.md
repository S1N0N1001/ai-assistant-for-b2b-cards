# Step 5 MVP-service

Дата: 02.11.2026. Статус: получение и структурная проверка входов завершены; реальная генерация ожидает настройки API.

## Цель
Принять два предоставленных пользователем товара и подготовить их к реальному прогону без добавления характеристик.

## Выполнено
- Сохранены examples/inputs/product_01.json (манометр ДМ02-100, Метер) и product_02.json (термометр ТБ-1, Росма).
- Из description удалены только [reference:0] и [reference:2]. Исходные описания с маркерами, происхождение и факт обработки сохранены в examples/SOURCE_DATA.md.
- Все технические значения и формулировки перенесены без изменения. Факты из description не дублировались вручную в specs.
- Текущим провайдером оставлен Anthropic, поскольку клиент уже реализован; пользователь провайдера не выбирал. Смена допустима отдельным шагом, если доступного аккаунта нет.
- Обновлены статус, заметки о генерации, README, ограничения и комплект сдачи.

## Проверки
Команда для каждого входа: `python -m service examples/inputs/product_01.json --validate-only` и аналогично product_02.json.
Ожидаемый и подтверждаемый результат: valid=true, missing_fields=[].
Это проверка структуры и минимальной достаточности входа; подлинность паспортных данных и полнота свойств не подтверждены. Внешние ссылки для маркеров не предоставлены.

## Необходимый флаг
Для шага 6 требуется локальный доступ к Anthropic: ANTHROPIC_API_KEY и ANTHROPIC_MODEL. Ключ в чат и Git не передаётся. Если аккаунта Anthropic нет, до реальных запросов выбираем доступного пользователю провайдера и адаптируем клиент отдельным зафиксированным шагом.

## Следующий результат
Два фактических API-ответа, сохранённые JSON/Markdown-карточки, длины SEO-полей и ручная сверка технических утверждений. До этого итоговые примеры не считаются готовыми.
