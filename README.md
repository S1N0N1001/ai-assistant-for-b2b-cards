# MVP: AI-помощник для B2B-карточек

Локальная консольная программа принимает JSON прибора и обращается к Groq Chat Completions API. Возвращает SEO-заголовок, описание, характеристики, поисковые запросы, commercial-блок и предупреждения. Результат является черновиком для проверки человеком.

## Статус

Основной CLI использует контракт 2.0: Groq выбирает идентификаторы допустимых блоков, сервис проверяет план и собирает текст из исходных данных. Все 27 тестов и два реальных прогона проверены. Готовые примеры: examples/outputs/product_01_selected.json/.md и product_02_selected.json/.md; сводная проверка — examples/outputs/SELECTED_REVIEW.md. Описания имеют 999 и 937 символов. Запуск без сторонних пакетов проверен в свежем локальном .venv. Публикация репозитория ещё не выполнена.

История: свободная генерация 1.x была отклонена по фактам/длине, затем подготовлены отдельные локальные grounded-редакции. Они сохранены для разбора и не заменяют реальные selected-прогоны 2.0. Исходные товары — в examples/inputs; demo_synthetic.json остаётся синтетическим.

## Требования и установка

Репозиторий проекта: https://github.com/S1N0N1001/ai-assistant-for-b2b-cards . Адрес предоставлен пользователем; статус первой публикации фиксируется в Step 16 MVP-service.md.

После публикации получить код можно командами:

```powershell
git clone https://github.com/S1N0N1001/ai-assistant-for-b2b-cards.git
cd ai-assistant-for-b2b-cards
```

Python 3.12 или новее, доступ в интернет для генерации, ключ Groq и доступная вашему аккаунту текстовая модель с поддержкой JSON Object Mode. Текущая настройка — openai/gpt-oss-120b на Groq; доступ пользователя к модели подтверждён прежними запросами, новый контракт 2.0 ещё требует прогона. Сторонние Python-зависимости не нужны. Проверено на Python 3.12.14 под Windows.

Получите папку проекта и откройте в ней терминал. Команды ниже используют python; если в Windows эта команда недоступна, используйте py -3.12 или полный путь к установленному интерпретатору.

```powershell
python --version
python -m venv .venv
```

Активация окружения не обязательна. На Windows вместо python можно использовать .\.venv\Scripts\python.exe; на Linux/macOS — .venv/bin/python. Установка через pip не требуется, запуск выполняется из корня проекта.

## Проверка без ключа и расходов

```powershell
python -m service examples/inputs/demo_synthetic.json --validate-only
python -m unittest discover -s tests -v
```

validate-only проверяет входные поля; он не проверяет качество генерации и не ищет смысловые противоречия. Тесты подменяют сетевой транспорт, не обращаются к API и не тратят средства.

## Настройка API

Создайте ключ в https://console.groq.com/keys и задайте GROQ_API_KEY и GROQ_MODEL в локальном окружении. Ключ не отправляйте в чат, документацию или Git. .env.example — образец имён переменных; .env автоматически не читается.

В PowerShell ключ можно ввести скрыто и перенести в окружение только текущего процесса:

```powershell
$apiCredential = Get-Credential -UserName 'api' -Message 'Введите API-ключ в поле пароля'
$env:GROQ_API_KEY = $apiCredential.GetNetworkCredential().Password
$env:GROQ_MODEL = 'openai/gpt-oss-120b'
$env:LLM_TIMEOUT_SECONDS = '45'
```

На Linux/macOS задайте те же переменные средствами вашего менеджера секретов или оболочки. Значение модели по умолчанию в коде намеренно отсутствует. Входные данные передаются Groq; расходуются лимиты аккаунта, на платном тарифе возможны расходы. Используется фиксированный HTTPS endpoint https://api.groq.com/openai/v1/chat/completions с Bearer-авторизацией и response_format=json_object. JSON Object Mode не гарантирует соответствие нашей схеме: локальные проверки обязательны. Текущая совместимость с аккаунтом требует реального прогона.

## Генерация

```powershell
python -m service examples/inputs/demo_synthetic.json --output output/demo-card.json
```

Сохраняются output/demo-card.json и output/demo-card.md. Для повторной генерации выберите новое имя: существующие файлы не перезаписываются. Не размещайте чувствительные данные в демонстрационных файлах.

## Вход

JSON в UTF-8, объект с полями name, manufacturer, specs и description. specs — объект, имена характеристик непустые, значения — строки либо null. Полный пример структуры находится в examples/inputs/demo_synthetic.json.

Минимум: непустое name и непустые технические сведения в specs или description. Пропуски перечисляются в missing_fields; неизвестные поля не используются. Числа в specs передавайте строками с единицами, например "1 МПа". Лимит входа — 100 000 символов.

## Выход и статусы

В режиме 2.0 модель управляет порядком всех характеристик, выбором одного из допустимых заголовков и 3–5 заранее сформированных запросов. Значения, описание с условиями применения и commercial-блок не пересказываются моделью. Результат содержит selection_plan, SHA-256 нормализованного входа, UTC-время и assembly_mode=llm_selection_source_template. Если модель дважды возвращает недопустимый план, выполнение завершается ошибкой без карточки. Локальная сборка не подменяет отсутствующий API-ответ.

Объём шаблона не гарантируется для произвольного товара: короткие и длинные источники могут дать needs_revision. Входные противоречия и достоверность паспортных данных проверяются человеком. Для двух предоставленных входов длины проверены локально. Способ сборки прямо указан в метаданных и предупреждениях.

seo_title — до 70 символов; seo_description — 800–1200 символов; search_queries — 3–5 разных запросов. Длина считается после обрезки пробелов по краям с внутренними пробелами и пунктуацией.

characteristics переносится из specs с source, без генерации моделью. Если сведения даны только в description, они остаются в source_description и могут использоваться в тексте; автоматического извлечения в список характеристик пока нет.

- needs_review: формальные проверки пройдены, требуется ручная сверка фактов.
- needs_revision: нарушены требования или модель сообщила о конфликте; результат требует исправления.
- Код завершения 0: проверка входа успешна или сохранён needs_review.
- Код 2: ошибка ввода, конфигурации, API, структуры ответа или файлов.
- Код 3: сохранён needs_revision.

При ошибках плана возможен один запрос исправления. При временной ошибке API возможен один сетевой повтор каждого запроса. Верхняя граница — четыре HTTP-попытки на запуск. Успешный код завершения не означает подтверждённой достоверности исходных данных.

## Типовые проблемы

- Не найден python: установите Python 3.12+ или укажите путь к нему.
- Нет ключа/модели: задайте переменные окружения в том же терминале.
- HTTP 401/403: проверьте ключ и права; 404 — имя модели; 429 — лимиты.
- Таймаут: проверьте сеть; LLM_TIMEOUT_SECONDS допускает от 1 до 120.
- Неверный JSON или тип: исправьте вход согласно схеме.
- Выход уже существует: задайте другое имя после --output.
- needs_revision: прочитайте warnings и conflicts, уточните данные; не публикуйте такой текст как готовую карточку.
