Ограничения и возможные улучшения

Обновление шага 16: код и комплект документов опубликованы в main репозитория https://github.com/S1N0N1001/ai-assistant-for-b2b-cards . Ожидание публикации в исторических записях ниже закрыто. Публичность не менялась; при закрытом доступе проверяющему нужны права GitHub.

Актуализация шагов 14–15: два реальных результата контракта 2.0 (product_01_selected и product_02_selected) проверены по планам, хешам и фактам. Все 27 тестов пройдены, запуск проверен в свежем локальном .venv. Упоминания ожидания прогонов ниже относятся к состоянию начала шага 14 и теперь закрыты. Публикация репозитория ещё не выполнена. Сохраняются ограничения шаблонного рендеринга, SEO-каталога и ручной проверки исходных данных.

Обновление шага 14: основной CLI переведён на выбор идентификаторов из исходного каталога и контролируемую сборку (промпт 2.0). Это осознанное ограничение творческой роли LLM. Неизвестные ID, пропущенные характеристики и новые текстовые поля отклоняются; значения моделью не переписываются. Локальные тесты пройдены, реальный новый контракт пока не проверен. Далее в таблице отражена также история проблем свободной генерации.

Новый режим не проверяет истинность источника и не разрешает его противоречия. Исходное описание копируется целиком, включая возможные ошибочные или посторонние фразы; перед публикацией человек проверяет его. Не гарантируется длина 800–1200 на произвольном входе. Перестановка блоков и выбор запросов могут меняться между запусками. Консервативные запросы ограничены названием, производителем и нейтральными словами, а не являются полноценным исследованием SEO-спроса.

Состояние на 02.11.2026: реальные прогоны первого товара выполнены, но свободная генерация отклонена по длине и/или фактам. Добавлена отдельная честно маркированная шаблонная сборка из исходных данных; первый шаблонный пример проверен. Второй API-пример ожидается.

Шаблонный режим не является свободной генерацией LLM и не доказывает соответствие генеративного сценария исходному заданию. Это консервативный альтернативный способ получить проверяемый черновик. На произвольном входе объём может нарушаться, что даёт needs_revision. Эвристические проверки свободного текста не являются полной проверкой фактов.

| Ограничение | Влияние и текущая обработка | Улучшение и приоритет |

| --- | --- | --- |

| Свободные API-ответы не прошли приёмку | Прогоны обоих товаров есть, но нарушены длины и достоверность | Высокий: ограничить генерацию выбором проверяемых фактов и контролируемой сборкой |

| Шаблонные примеры не являются свободной генерацией | Два local_source_template примера сохранены и проверены отдельно | Высокий: раскрыть компромисс и закрыть генеративный критерий |

| Ложные срабатывания категорий | Уточнение отсутствующей калибровки ошибочно отмечается как выдумка | Средний: различать утверждения и уточнения; эвристика не доказывает ложность |

| Свободный текст может содержать галлюцинации | Проверки чисел и строгий промпт не доказывают истинность; всегда требуется человек | Высокий: сверка утверждений с цитатами источника |

| Противоречия ищет модель | Возможны пропуски; найденные конфликты дают needs_revision | Высокий: отдельная нормализация технических значений |

| Характеристики только из specs | Паспорт не преобразуется в таблицу; исходное описание сохраняется | Средний: извлечение с точными цитатами и подтверждением |

| Проверка чисел эвристическая | Число из одной характеристики может ошибочно попасть в другую; пересчёт единиц может быть отклонён | Средний: проверка пар параметр–значение–единица |

| Скудные данные и длина 800–1200 | Модель может не соблюсти объём; один запрос исправления, затем needs_revision | Высокий: уточнение входных данных, редакторская проверка |

| Внешний API и расходы | Нужны сеть и ключ, до четырёх HTTP-попыток; стоимость не рассчитывается | Средний: учёт usage и бюджета |

| Недетерминированность | Повторная генерация может отличаться | Средний: сохранять метаданные реальных прогонов и версии |

| Локальный CLI | Нет формы, массового ввода и редактора | Низкий: простая веб-форма после проверки качества |

| Сохранение двух файлов не транзакционно | Если вторая запись не удалась, первый файл может остаться; CLI вернёт ошибку | Средний: атомарное сохранение комплекта |

| Вход читается до проверки длины | Большой локальный файл сначала попадает в память | Низкий: потоковое ограниченное чтение |

| Нет опубликованного репозитория | Локальный Git не является ссылкой для сдачи | Высокий: выбрать размещение и проверить доступ |

Полноценные CMS, БД, деплой, векторный поиск и поддержка нескольких провайдеров не входят в текущий MVP. Приоритеты улучшений пересматриваются после реальных прогонов; оценки времени до этого не фиксируются.
